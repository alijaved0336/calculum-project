# Resource Integrity Maintenance (Subresource Integrity)

## Description

This document explains how to maintain `integrity` attributes in HTML files when JavaScript scripts are updated in CloudFront. The `integrity` attributes verify that remote resources have not been modified using SHA-384 hashes.

## When to Recalculate Hashes?

Recalculate hashes when:
- A JavaScript script is updated in CloudFront
- A new remote script is added to HTML files
- SonarQube reports that a remote resource is missing the `integrity` attribute
- A script version changes in CloudFront

## Update Process

### Step 1: Recalculate Hashes

Run the script that downloads current files from CloudFront and calculates their SHA-384 hashes:

```bash
node scripts/calculate-integrity-hashes.js
```

**What this script does:**
- Downloads all scripts from CloudFront for the three environments (dev, pro, pre)
- Calculates the SHA-384 hash of each file
- Saves the results in `integrity-hashes.json`

**Expected output:**
```
=== Calculando hashes de integridad para scripts CloudFront ===

Descargando https://d31zvqb0ivkacw.cloudfront.net/d/script.js...
✅ script.js (dev): sha384-71LDudOgJfK27OTL/OnuHnCjPvgBAxrZw8/MQ9x4oy0KVaD/yDYD1bkFQSf7at5I
...
✅ Hashes guardados en: integrity-hashes.json
```

### Step 2: Update HTML Files

Once the hashes have been recalculated, update the HTML files with the new values:

```bash
node scripts/update-html-integrity.js
```

**What this script does:**
- Reads the `integrity-hashes.json` file with the calculated hashes
- Finds all `<script>` tags with remote `src` in HTML files
- Adds or updates the `integrity` attribute with the corresponding hash
- Preserves the original format of HTML files

**Expected output:**
```
=== Actualizando archivos HTML con atributos integrity ===

✅ Agregado integrity a script.js (dev) en signin.html
✅ Agregado integrity a script.js (pro) en signin.html
...
✅ Proceso completado. 24 archivos actualizados.
```

### Step 3: Verify Changes

Verify that changes were applied correctly:

1. **Review an updated HTML file:**
   ```bash
   # Example: verify signin.html
   grep -A 5 "script.js" public/b2cDev/signin.html
   ```

2. **Verify that the integrity attribute is present:**
   The `<script>` tag must include the `integrity` attribute:
   ```html
   <script
     type="application/javascript"
     src="https://d31zvqb0ivkacw.cloudfront.net/d/script.js"
     integrity="sha384-71LDudOgJfK27OTL/OnuHnCjPvgBAxrZw8/MQ9x4oy0KVaD/yDYD1bkFQSf7at5I"
     crossorigin="anonymous"
     defer
   ></script>
   ```

3. **Test in the browser:**
   - Open the application in the browser
   - Check the developer console for any integrity-related errors
   - If a hash is incorrect, the browser will block the script load and display an error in the console

## Available Scripts

### `scripts/calculate-integrity-hashes.js`

**Purpose:** Downloads files from CloudFront and calculates SHA-384 hashes.

**Usage:**
```bash
node scripts/calculate-integrity-hashes.js
```

**Files it processes:**
- `script.js`
- `reset_pwd.js`
- `forgot_pwd.js`
- `signup_step_1.js`
- `signup_step_2.js`
- `totp.js`
- `email_idpselector.js`

**Environments:**
- Dev: `https://d31zvqb0ivkacw.cloudfront.net/d/`
- Pro: `https://d31zvqb0ivkacw.cloudfront.net/p/`
- Pre: `https://d31zvqb0ivkacw.cloudfront.net/s/`

**Output:**
- Generates/updates `integrity-hashes.json` in the project root (temporary file, not committed to repository)

### `scripts/update-html-integrity.js`

**Purpose:** Updates HTML files with `integrity` attributes based on `integrity-hashes.json`.

**Usage:**
```bash
node scripts/update-html-integrity.js
```

**Files it updates:**
- `public/b2cDev/*.html` (8 files)
- `public/b2cPro/*.html` (8 files)
- `public/b2cPre/*.html` (8 files)

**Behavior:**
- Only updates scripts that do NOT already have the `integrity` attribute
- If a script already has `integrity`, it updates it with the new hash
- Preserves the original file format (multiple lines, indentation, etc.)

## `integrity-hashes.json` Structure

**Note:** This is a temporary file that is automatically generated by `calculate-integrity-hashes.js` and is not committed to the repository. It is used only during the update process and can be safely deleted after the HTML files are updated.

The `integrity-hashes.json` file has the following structure:

```json
{
  "script.js": {
    "dev": "sha384-71LDudOgJfK27OTL/OnuHnCjPvgBAxrZw8/MQ9x4oy0KVaD/yDYD1bkFQSf7at5I",
    "pro": "sha384-NRKKbxVrhK5akoXEJZNXW4sjshLbZUyprkHvvFtEEwok3EVWc2TST5mlIGFE0ek+",
    "pre": "sha384-DIy2Zwh886ei0dd6zASBzZQRk/L3Ktjte1uUeGF5YdH4fi9mjs3iy49P3rl4eC6L"
  },
  "reset_pwd.js": {
    "dev": "sha384-gBhmD6NCZwfZg3EcUA/ojU7lWnQ7qngjDinW3OH4PgV3L3+YTH3NIgrWsziIh54L",
    ...
  }
}
```

## Adding a New Remote Script

If you need to add a new remote script to HTML files:

1. **Add the script to the `SCRIPTS` array in `calculate-integrity-hashes.js`:**
   ```javascript
   const SCRIPTS = [
     'script.js',
     'reset_pwd.js',
     // ... other scripts
     'new_script.js'  // ← Add here
   ];
   ```

2. **Run the complete process:**
   ```bash
   node scripts/calculate-integrity-hashes.js
   node scripts/update-html-integrity.js
   ```

3. **Add the `<script>` tag in the corresponding HTML files:**
   The `update-html-integrity.js` script will automatically add the `integrity` attribute when it finds the tag.

## Troubleshooting

### Error: "Failed to download"
**Cause:** The file does not exist in CloudFront or the URL is incorrect.

**Solution:**
- Verify that the script URL is correct
- Confirm that the file exists in CloudFront
- Check internet connectivity

### Error: "No se encontró hash para..." (Hash not found for...)
**Cause:** The script is not in the list of processed scripts or the environment does not match.

**Solution:**
- Verify that the script name is in the `SCRIPTS` array
- Confirm that the CloudFront path matches the environment (d/, p/, s/)

### Browser blocks the script
**Cause:** The hash in the `integrity` attribute does not match the current file.

**Solution:**
1. Recalculate hashes: `node scripts/calculate-integrity-hashes.js`
2. Update HTML files: `node scripts/update-html-integrity.js`
3. Verify that the file in CloudFront has not changed since the hash was calculated

### Script does not update in HTML files
**Cause:** The script already has an `integrity` attribute (even if incorrect).

**Solution:**
- The `update-html-integrity.js` script updates existing hashes
- If the problem persists, manually verify the `<script>` tag format in the HTML

## Best Practices

1. **File versioning:** Ideally, files in CloudFront should be versioned (e.g., `script.v1.2.3.js`) to avoid unexpected changes.

2. **Review before updating:** Before updating hashes, verify which files changed in CloudFront.

3. **Test locally:** After updating hashes, test the application locally to ensure scripts load correctly.

4. **Temporary hash file:** The `integrity-hashes.json` file is temporary and is automatically generated when needed. It is excluded from version control (`.gitignore`) and can be safely deleted after updating HTML files.

5. **Document changes:** If you manually update a script in CloudFront, document the change and recalculate hashes immediately.
